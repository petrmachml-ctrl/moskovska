# Public preview delivery

Source has been pushed to the selected public GitHub repository, branch main. GitHub Pages activation was attempted with the existing integration and returned HTTP 403 `Resource not accessible by integration`. No secret values were requested or replaced, and the environment configuration was not republished. Official `actions/configure-pages` documentation confirms that first-time enablement requires a token other than workflow GITHUB_TOKEN with the relevant administration/Pages permissions, so a predictably failing workflow was not added.

Auxiliary preview: raw.githack.com serves the already-public repository as HTML with the appropriate web content types. A full commit SHA in the URL fixes the delivered version. In a browser it may first show its own External Content Notice and Open the page button. This service interstitial is not part of the app; the auxiliary URL is not being represented as proper GitHub Pages activation or a production hosting guarantee.

For the initial released revision, index.html, styles.css, app.js, data/units.js, all three images and both self-hosted font files were downloaded over verified HTTPS and matched local SHA-256 hashes. WebP responses redirect to raw.githubusercontent.com; following the documented redirects resolves the actual image bytes. Header/footer home links explicitly target index.html to work on both directory-based hosting and a file-serving CDN.

Public-browser verification initially stopped at a cloud proxy CA trust error in the sandboxed shell. In the approved external shell context HTTPS verification succeeded, but the first loaded HTML was the provider's External Content Notice rather than the app. No certificate validation was disabled. HTTP 200 on a provider interstitial was not counted as a successful app verification.

The provider's ordinary Open the page action was then followed. For app revision `2daa319700d3500c40c250150e9e38168d952188`, public Chromium checks passed at 1440 × 1000 and 390 × 844: exterior/interior images decoded, local fonts loaded, eight units rendered, the preview label was visible, direct B3.1 inquiry opened and focused its first field, and the home link returned to the same working page. These are auxiliary-preview smoke checks, not a claim that GitHub Pages was enabled or that the full 14-case suite ran against the public URL. The complete 14-case suite passed locally against the final application build.
