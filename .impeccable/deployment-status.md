# Public preview delivery

Source has been pushed to the selected public GitHub repository, branch main. GitHub Pages activation was attempted with the existing integration and returned HTTP 403 `Resource not accessible by integration`. No secret values were requested or replaced, and the environment configuration was not republished. Official `actions/configure-pages` documentation confirms that first-time enablement requires a token other than workflow GITHUB_TOKEN with the relevant administration/Pages permissions, so a predictably failing workflow was not added.

Auxiliary preview: raw.githack.com serves the already-public repository as HTML with the appropriate web content types. A full commit SHA in the URL fixes the delivered version. In a browser it may first show its own External Content Notice and Open the page button. This service interstitial is not part of the app; the auxiliary URL is not being represented as proper GitHub Pages activation or a production hosting guarantee.

For the initial released revision, index.html, styles.css, app.js, data/units.js, all three images and both self-hosted font files were downloaded over verified HTTPS and matched local SHA-256 hashes. WebP responses redirect to raw.githubusercontent.com; following the documented redirects resolves the actual image bytes. Final revised version needs the same HTTP check after its source commit is pushed. Header/footer home links explicitly target index.html to work on both directory-based hosting and a file-serving CDN.

Public-browser verification initially stopped at a cloud proxy CA trust error in the sandboxed shell. In the approved external shell context HTTPS verification succeeded, but the first loaded HTML was the provider's External Content Notice rather than the app. No certificate validation was disabled. Public HTTP resource validation and local Playwright functional/accessibility results are distinct evidence; HTTP 200 on a provider interstitial is not being counted as a successful app verification.

The owner can activate the preferred GitHub Pages URL through repository Settings → Pages, Deploy from a branch → main → /(root) → Save. README contains the settings link. This external permission requirement remains outstanding until the owner saves that setting and the resulting actual page is verified. The user has been asked for this prerequisite through the asynchronous question tool; this is not another request for publication authorization.
